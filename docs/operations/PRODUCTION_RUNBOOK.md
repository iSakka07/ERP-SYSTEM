# دليل تشغيل ERP-SYSTEM V1

هذا الدليل لتشغيل نسخة عرض مستقرة أو نسخة إنتاج داخل خادم واحد. قاعدة البيانات الحالية SQLite؛ لذلك يعمل التطبيق على **نسخة تطبيق واحدة** مع قرص دائم للقاعدة والنسخ الاحتياطية. لا تشغّل أكثر من instance فوق ملف SQLite نفسه.

## قبل التشغيل

1. جهز Node.js وpnpm 11، ومجلدًا دائمًا للتطبيق والقاعدة والنسخ الاحتياطية.
2. أنشئ ملف `.env.production.local` خارج Git، ولا تنسخه من بيئة التطوير كما هو.
3. اضبط القيم التالية:

```env
DATABASE_URL="file:/مسار-دائم/erp.db"
AUTH_SECRET="سر-عشوائي-فريد-أطول-من-32-حرفًا"
AUTH_URL="https://erp.example.com"
BOOTSTRAP_ADMIN_NAME="مدير النظام"
BOOTSTRAP_ADMIN_EMAIL="admin@example.com"
BOOTSTRAP_ADMIN_PASSWORD="كلمة-مرور-قوية-وفريدة"
```

4. اجعل الموقع خلف HTTPS حقيقي. يرفض النظام عند تسجيل الدخول سر الجلسة الضعيف أو `AUTH_URL` غير الآمن في الإنتاج.
5. لا تستخدم `db:demo-setup` على بيانات العميل.

## أول تشغيل

```bash
pnpm install --frozen-lockfile
pnpm db:setup
pnpm verify:production-env
pnpm build
pnpm start --port 3090
```

`db:setup` ينشئ دليل الحسابات، البنك الرئيسي وصلاحياته بالإضافة إلى المستخدم الإداري الأول. راجع الدخول بحساب المدير، ثم غيّر كلمة مروره وأنشئ حسابات الشركة الفعلية.

بعد أن يصبح الخادم متاحًا عبر HTTPS، اضبط فحص صحة مزود الاستضافة على `GET /api/health`. النتيجة الصحيحة هي `{"status":"ok"}`؛ أي نتيجة `503` تعني عدم جهوزية قاعدة البيانات أو الترحيلات.

## قبل كل تحديث

```bash
pnpm db:backup
pnpm db:verify-backup
pnpm db:migrate
pnpm build
```

لا تعدّل migration سبق تطبيقه؛ المشغّل يرفض ذلك عبر checksum. إذا فشل ترحيل، أوقف النشر واستعد من النسخة الاحتياطية بدل تعديل قاعدة العمل يدويًا.

## الاستعادة المختبرة

1. أوقف التطبيق.
2. احتفظ بنسخة من ملف قاعدة البيانات الحالي قبل استبداله.
3. انسخ ملف النسخة الاحتياطية الذي تحقّق منه إلى مسار `DATABASE_URL` الدائم.
4. شغّل `pnpm db:verify-backup` على النسخة ثم `pnpm db:migrate`.
5. شغّل التطبيق، وسجّل الدخول، وراجع آخر قيد وحركة بنك وصندوق قبل فتحه للمستخدمين.

## قواعد العرض للعميل

- بيئة العرض منفصلة تمامًا عن بيانات العمل؛ استخدم `pnpm db:demo-setup` فيها فقط.
- استخدم HTTPS حتى في رابط العرض العام، ولا تشارك حساب المدير الافتراضي.
- لا تعرض مرفقات حقيقية أو بيانات رواتب واقعية.
- نفذ يوميًا نسخة احتياطية واختبر استعادة دورية قبل تحويل العرض إلى استخدام تشغيلي.

## حدود V1

V1 لا يتضمن بعد تشغيلًا متعدد الخوادم، تخزين مرفقات خارجي، أو قوائم قانونية/ضريبية نهائية. أي تشغيل متعدد instances يحتاج نقل قاعدة البيانات ومخزن rate-limit إلى خدمات مشتركة قبل التوسع.
