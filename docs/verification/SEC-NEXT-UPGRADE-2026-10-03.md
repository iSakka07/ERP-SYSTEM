# SEC-NEXT — تحديث Next.js الأمني

التاريخ: 2026-10-03.

الحالة: **مغلق في المصدر والاختبار المحلي؛ تطبيق الإصلاح على الاستضافة يتطلب نشر البناء الجديد والتحقق منه.**

## النطاق والتغيير

- تحديث `next` و`eslint-config-next` من `16.3.5` إلى `16.3.8` بأرقام ثابتة.
- تحديث `pnpm-lock.yaml` لحزم Next.js التابعة وربط `next-auth` بالإصدار الجديد.
- مراجعة فرق lockfile: التغييرات محصورة في عائلة Next.js ومراجعها؛ إصدارات React وNextAuth وPrisma لم تتغير.
- إضافة `scripts/test-runtime-smoke.mjs` والأمر `test:runtime-smoke` مع إتاحته بالاختيار عبر غلاف `test:isolated-api`.
- لا توجد تغييرات في منطق الإنتاج أو مخطط البيانات أو migrations ضمن هذا الإصلاح.

## سبب اختيار الإصدار

التنبيه [GHSA-vcvr-r3jv-pc5j](https://github.com/vercel/next.js/security/advisories/GHSA-vcvr-r3jv-pc5j) يحدد `16.3.6` كأول إصلاح. اختير `16.3.8` للحصول على الإصلاحات الأمنية الإضافية ضمن سلسلة `16.3` نفسها، وفق [ملاحظات الإصدار](https://github.com/vercel/next.js/releases/tag/v16.3.8).

الثغرة المذكورة تتطلب تمرير بيانات يتحكم فيها المهاجم إلى SVG عبر تنفيذ Node.js لـ`next/og ImageResponse`. البحث في `src` لم يجد استخدامًا لهذه الوظيفة. لذلك التنبيه السابق يثبت وجود إصدار متأثر في الاعتماديات، ولا يثبت قابلية استغلال التطبيق أو وقوع اختراق.

## ما يغطيه اختبار التشغيل

يستخدم الغلاف قاعدة SQLite مؤقتة وخادم `next start` ببناء إنتاجي. يرفض الاختبار العمل ما لم يكن مسار القاعدة داخل `tmp/isolated-test-*/test.db` وعنوان الخادم محليًا.

- صفحة الدخول والملفات العامة وhealth.
- تحويل الزائر غير المسجل إلى الدخول، ورفض API غير المصرح بـ401.
- دخول المدير والمبيعات والتحقق من الجلسات.
- رفض دور المبيعات عند محاولة قراءة البنك أو إنشاء حركة أو تنزيل مرفق بنكي.
- استجابات HTML لـ14 صفحة بعد الدخول: الرئيسية، الوارد، المقاولون، المشتريات، المخزن، البنك، المحاسبة، الرواتب، النثريات، المرفقات، إدارة الحسابات، وصفحات إنشاء الوارد والمقاول والمشتريات.
- رفض Origin خارجي.
- إنشاء حركة تمويل بنكية بمرفق موصوف، إعادة نفس الطلب دون إنشاء حركة ثانية، ورفض تعديل payload مع نفس المفتاح.
- وجود القيد المحاسبي، وتنزيل محتوى المرفق بالحساب المصرح.
- عكس الحركة ووجود قيد عكسي واحد.
- تسجيل الخروج وإبطال جلسة سابقة عبر `sessionVersion`.

هذه اختبارات HTTP/قاعدة بيانات، وليست اختبار متصفح لتفاعل الواجهة أو توليد PDF. لم يُشغّل قبول PostgreSQL أو حزمة القبول المالية الكاملة في هذا البند؛ أعطال fixtures المعروفة في تلك الحزمة تبقى ضمن بند الاختبارات المالي.

## إعادة التشغيل — PowerShell

```powershell
$env:ERP_ISOLATED_POSTGRES = 'false'
$env:ERP_TEST_ONLY = 'test:runtime-smoke'
pnpm test:isolated-api
Remove-Item Env:ERP_TEST_ONLY
Remove-Item Env:ERP_ISOLATED_POSTGRES
```

يشغّل الغلاف migrations والتهيئة على قاعدة الاختبار فقط، ويبني `.next-test`، ثم يوقف خادم الاختبار ويحذف القاعدة المؤقتة.

## النشر

لم ينفذ نشر إلى الاستضافة في هذه الجولة. عند النشر يلزم تثبيت الاعتماديات من القفل، وإنشاء بناء إنتاجي جديد، وإعادة تشغيل الخدمة، ثم فحص health والدخول والصفحات المحمية. لا تستخدم build قديمًا مبنيًا على 16.3.5. تعطل النشر لا يعالج بإعادة تشغيل الإصدار المتأثر كحل دائم.
