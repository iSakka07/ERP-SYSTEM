# مراجعة إغلاق SEC-01 إلى SEC-06

تاريخ المراجعة: 2026-09-28

## النتيجة التنفيذية

| البند | الحالة | نتيجة الاختبار الفعلي |
|---|---|---|
| SEC-01 | مغلق | صفحة الإدارة لم ترسل راتب الاختبار أو الموظف أو المشروع خارج نطاق المهندس. |
| SEC-02 | مغلق | صفحة الوارد لم ترسل اسم مرفق أو سبب إجراء لمشروع آخر، وتنزيل المرفق أعاد 403. |
| SEC-03 | مغلق | جرد مخزن مشروع آخر رُفض 403 ولم ينشئ حركة أو قيدًا. |
| SEC-04 | مغلق | طلب تعديل مصادق من Origin مخالف رُفض 403، وكل مسارات التعديل تستخدم الآن منطق الحماية المركزي. |
| SEC-05 | مغلق | حساب يملك `warehouse.view` فقط لم يتلق `paidCents` أو `totalCents` في سجل الاستلام، والتفاصيل تحذف أسعار وقيم السطور. |
| SEC-06 | مغلق | حساب المحاسب رُفض 403 وبقي الكشف `APPROVED`، وصلاحية الصرف منفصلة في الخادم والواجهة. |

## الأدلة

- SEC-01: الاستعلامات تستخدم نطاق مشروعات المهندس وحقول `select` محددة، واختبار HTML/RSC أعاد `leaksSalary=false` و`leaksOtherEmployee=false` و`leaksOtherProject=false`.
- SEC-02: المرفقات وسجل التدقيق مقيدان بمعرفات العقود والمستخلصات المسموح بها. اختبار الصفحة أعاد `leaksAttachmentName=false` و`leaksAuditReason=false`، والتنزيل خارج النطاق أعاد 403.
- SEC-03: `assertWarehouseProject` يُستدعى للمخازن المصدر والوجهة والجرد. اختبار الجرد خارج النطاق أعاد 403 ولم يغيّر القيود.
- SEC-04: كل مسارات التعديل تعتمد الآن على منطق Origin المركزي، مع رفض Origin المخالف ونوع المحتوى غير المقبول.
- SEC-05: سجل وتفاصيل الاستلام يمران `includeFinancial` بحسب `purchases.view`. اختبار قارئ المخزن أعاد بيانات تعريف الفاتورة بلا حقول مالية.
- SEC-06: `salaries.pay` منفصلة عن `salaries.manage`، أزيلت من دور `accountant` مع تنظيف منح الدور القديمة، وأصبح زر الصرف يعتمد على `canPay` مستقلًا. اختبار المحاسب أعاد 403 وبقي الكشف معتمدًا.
